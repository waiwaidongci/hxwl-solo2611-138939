# 印染车间蒸汽单耗异常排查

`hxwl-solo2611-13` · 稳健统计与离群检测

合并染色批报的完工时间、配方和干布净重，以及分机蒸汽表的批次用量。值班工艺员按工况找出偏高和偏低的蒸汽单耗，安排当班复测并交接给能源计量组。

## 模拟客户与工作流

临澜染整厂二车间（模拟），4 台间歇式染机、42 名员工，昼夜两班交接。

- 不同配方沿用一条月均线，换方后经常误报。
- 月底重算时把异常批和之后几天一起算进基准，现场无法复现报警。
- 稳定工况的批次单耗经常相同，原 Excel 标准化公式分母为零。

工艺值班组优先核查偏高批的保温时长、蒸汽阀和疏水器。能源计量组核对偏低批的抄表起止读数、旁路和干布净重。历史不足的工况补齐同组批次后重算，复核结论随排查单交接。

## 业务模块

- 染缸用汽台账
- 基线试算台
- 超差排查单
- 班组交接箱

## 计算口径

蒸汽单耗为批次蒸汽千克数除以该批干布净重。按染机、配方及完工班别分组，采用同组严格早于当前完工时刻且在回溯时限内的最近批次。厂区时刻按北京时间录入，08:00 至 19:59 属昼班，20:00 至次日 07:59 属夜班。历史充足后，计算中位数和绝对离差中位数 MAD。MAD 大于零时，阈值为稳健离差倍数 × 1.4826 × MAD。MAD 等于零时改用绝对容差。单耗与基线的绝对差严格大于阈值才标记，保留偏高或偏低方向。合法历史批次在窗口内参与计算，包含已标记批次。连续漂移可能逐步改变基线，判定只用于确定查账和复测顺序。

样例输入为 `临澜二车间_批次蒸汽抄表_1116-1124.csv`，见 `backend/demo/sample.csv`。相同输入与参数复现相同结果。格式错误在导入时提示，样本量或业务约束不满足时在后台运行结果中提示。

## 一班如何使用

1. 2026 年 11 月 24 日 07:10 交班时，夜班抄表员记下 LL-261124-A1N 的蒸汽用量 925 kg 和干布净重 500 kg。
2. 09:20 记下 1# 染机昼班批 LL-261124-A1D 的蒸汽用量 1,425 kg 和干布净重 500 kg。
3. 11:00 值班工艺员上传《临澜二车间_批次蒸汽抄表_1116-1124.csv》，核对 11 月 16 日至 24 日的 36 个完工批次。
4. 11:05 设最近 5 批、最少 4 批、回溯 14 天、稳健离差倍数 3.5 和零 MAD 容差 0.15 kg/kg，运行排查。
5. 11:10 定位 2 个偏高和 1 个偏低批。昼班 LL-261124-A1D 的基线是 2.05 kg/kg，夜班 LL-261124-A1N 的基线是 2.40 kg/kg。
6. 11:15 对历史不足的 16 批标记补证，在最近的偏高批先复测阀位和保温时长，同时复核夜班偏低批的抄表记录。
7. 11:25 把复核决定和含基线批号的排查单发给印染工艺值班组、能源计量组。

## 启动与本地开发

```sh
cp .env.example .env
docker compose up -d --build --wait
docker compose exec -T backend python -m scripts.seed_demo
```

停止本地服务可执行 `docker compose down`。仅清理演示数据时使用 `docker compose down -v --remove-orphans`。

浏览器 `http://127.0.0.1:18322`，API `http://127.0.0.1:19322`，数据库宿主端口 `17822`。

前端由 Nginx 提供原生 HTML/CSS/JS，并将 `/api/` 转发给 FastAPI。Python 3.11 Worker 使用 Redis 唤醒和 PostgreSQL 16 运行租约，生成的 CSV 由命名卷共享。可编辑 `frontend/src/pages`、`backend/src/services/analysis.py` 和 `backend/demo` 后执行 `docker compose up -d --build --wait`。Compose 默认映射到本机回环地址。更改 `.env` 可配置端口、数据库密码、JWT 密钥以及 `SEED_DEMO` 种子开关。演示凭据适用于本机模拟数据。

| 角色 | 账号 | 密码 | 工作内容 |
|---|---|---|---|
| 主管 | admin | admin-demo-2611 | 查看审计，复核运行，安排与停用分发计划 |
| 分析员 | analyst | analyst-demo-2611 | 导入 CSV、运行计算、下载结果 |
| 只读 | viewer | viewer-demo-2611 | 查看数据、结果和投递回执，下载 CSV |

角色、运行状态和复核状态在 `backend/src/constants/enums.py` 与 `frontend/src/constants/enums.js` 同步定义。角色参与登录、路由授权和工具栏控制。运行状态在 Worker、任务接口和结果页使用。复核状态在运行模型、复核接口和交付页使用。

核心实体为 CSV 数据批次、分析运行、分发计划及其投递回执。业务参数与真实模拟数据位于 `backend/demo/`。后端分为 routes、controllers、services、models、schemas 和中间件，前端分为 api、store、组件和业务页面。授权模式见 [LICENSE](LICENSE)。
